# 대시보드 디자인 규격

로컬 대시보드(`depbee dashboard`)에서 개발자는 먼저 어느 프로젝트를 검토할지 정하고, 그 프로젝트 안에서 후보와 검사 근거를 함께 읽습니다. 공통 색과 서체는 `src/depbee/dashboard/static/style.css`, 현황판의 비교 표와 모바일 배치는 같은 디렉터리의 `overview.css`에서 관리합니다.

## 1. 구조

**프로젝트 현황판이 시작 화면입니다.** 등록한 프로젝트가 없으면 폴더 선택으로 시작합니다. 하나 이상이면 프로젝트마다 최근 검사, 반영을 시도하지 않은 최신 미리보기, 마지막으로 성공한 반영을 비교합니다. 각 기록의 시각과 보고서 링크는 해당 실행에서 가져옵니다. 거부·실패·변경 없음으로 끝난 시도는 프로젝트의 **기록**에서 확인합니다.

큰 화면에서는 프로젝트 한 개가 한 행이고 세 기록의 열이 맞춰집니다. 좁은 화면에서는 프로젝트 이름 아래에 같은 순서로 세 기록이 쌓입니다. 옮긴 폴더도 예전 보고서를 열 수 있습니다. 실행 기록이 비어 있으면 비어 있는 종류를 명시합니다.

프로젝트를 열면 왼쪽 레일에서 프로젝트를 전환하고, 가운데 목록에서 패키지를 고르고, 오른쪽 패널에서 해당 후보의 근거를 읽습니다.

- 프로젝트 화면은 패키지, 업데이트, 기록 세 가지이고 프로젝트 이름 아래 탭으로 오갑니다.
- 패키지와 업데이트 화면은 후보를 고르면 페이지를 떠나지 않고 그 후보의 판정, 확인된 사실, 모델 점수, 검사 기준을 패널에 보입니다.
- 보고서(실행 화면, 미리보기 화면)의 항목은 "확인된 사실"과 "모델 점수"를 좌우로 나눕니다. 점수는 사실과 섞어 쓰지 않습니다.
- 저장된 값만 보입니다. 기록, 점수, 건수의 예시 값을 채워 넣지 않고, 없는 값은 "기록 없음"이나 "-"로 둡니다.

| `--ink-2` | `#213158` | 레일에서 열린 항목과 hover |
| `--surface` | `#f3f5f9` | 작업면 바탕 |
| `--sheet` | `#fff` | 표, 카드, 패널 |
| `--head` | `#e8ecf3` | 표 머리, 상태 문장, 빈 상태 |
| `--line` | `#d3d9e4` | 가는 구분선 |
| `--muted` | `#55607a` | 보조 글자(흰 바탕에서 6:1 이상) |
| `--link` | `#1c49b0` | 본문 링크 |
| `--honey` | `#f4b223` | 브랜드와 선택 표시 |
| `--honey-wash` | `#fff2c9` | 고른 행의 바탕 |
| `--risk`, `--risk-wash` | `#b3261e`, `#fdecea` | 위험, 멈추는 오류 |
| `--hold`, `--hold-wash` | `#5a3ea6`, `#efeafb` | 보류, 결정이 필요한 주의 |
| `--pass`, `--pass-wash` | `#1e6b58`, `#e6f2ee` | 통과 |

꿀색은 브랜드와 선택(열린 프로젝트, 열린 화면 탭, 고른 후보)에만 씁니다. 판정, 경고, 일반 버튼에는 쓰지 않습니다. 꿀색만으로는 대비가 부족하므로 선택 표시는 먹남색 테두리나 먹남색 바탕과 함께 씁니다.

## 3. 판정 표시

판정은 색, 육각 셀의 모양, 글자 세 가지로 함께 표시합니다. 색만으로 뜻을 전하지 않습니다.

| 판정 | 색 | 셀 모양(`.cell`) | 글자 |
| --- | --- | --- | --- |
| 위험 | `--risk` | 가득 채움(`.risk`) | 위험 |
| 보류 | `--hold` | 아래 절반 채움(`.hold`) | 보류 |
| 통과 | `--pass` | 가운데 점(`.pass`) | 통과 |
| 미확인, 삭제, 기록 없음 | `--muted` | 빈 셀(`.none`) | 미확인, 삭제 등 |
| 폴더 없음 | `--risk` | 빗금(`.gone`) | 폴더를 찾을 수 없음 |

- 목록과 패널에서는 `.verdict` 칩(셀과 글자)으로, 보고서 항목에서는 왼쪽 띠로 표시합니다. 보류의 띠는 끊어진 선입니다.
- 통과는 눈에 띄게 칠하지 않습니다. 통과는 모델의 판정일 뿐 안전 보증이 아니라는 문장을 모든 화면 아래에 둡니다.
- 기지 악성 기록 일치는 판정 칩 옆에 글자로 따로 적고, 낮은 점수가 이 경고를 취소하지 않는다는 문장을 함께 둡니다.

## 4. 글꼴과 크기

외부 글꼴은 받지 않습니다(CSP). 본문은 `--sans`(Pretendard, Apple SD Gothic Neo, 맑은 고딕 순), 식별자는 `--mono`(Cascadia Mono, Consolas 순)입니다.

- `--mono`는 패키지 이름, 버전, 설치 위치, 경로, 해시에만 씁니다. 비슷하게 생긴 글자를 구별해야 하는 값입니다.
- 크기는 0.8125rem(보조), 0.875rem(표 안의 식별자, 주석), 0.9375rem(표와 패널), 1rem(본문, 입력), 1.125rem(구역 제목), 1.5rem(화면 제목)만 씁니다. 브랜드 글자(1.25rem, 레일에서 1.375rem)만 예외입니다.
- 줄 높이는 본문 1.6, 표 1.45입니다. 한글은 `word-break: keep-all`로 낱말 단위로 줄을 바꾸고, 식별자는 `overflow-wrap: anywhere`로 어디서든 꺾습니다. 설명 문단의 폭은 46rem까지입니다.
- 라벨을 영문 대문자로 쓰거나 자간을 벌리지 않습니다. 숫자 열은 `tabular-nums`입니다.

## 5. 탐색

- 레일(80rem 이상): 브랜드, 등록한 프로젝트 탭(상태 셀, 이름, 최근 상태), 프로젝트 현황판, 프로젝트 관리, 모델 정보 순서입니다. 열린 항목은 `aria-current`와 꿀색 세로 띠로 표시합니다.
- 막대(80rem 미만): 레일이 위쪽 막대가 됩니다. 46rem 미만에서는 열린 프로젝트 하나만 막대에 두고, 다른 프로젝트는 프로젝트 관리와 현황판에서 고릅니다. 프로젝트 목록 전체를 본문 앞에 쌓지 않습니다.
- 후보 선택은 주소로 합니다. 고르는 링크는 `?item=<실행 번호>.<보고서 안 위치>#candidate-evidence`이고, 패키지 화면에서는 검색어(`q`, 퍼센트 인코딩)와 종류(`scope`)를 앞에 유지합니다. 주소에 `item`이 없으면 목록의 첫 후보가 열립니다.
- 고른 후보의 링크에는 `aria-current="true"`와 `id="picked"`가 붙습니다. 보고서의 해당 항목으로 가는 링크(`/runs/<실행>#r<위치>`)는 선택과 별개로 행과 패널에 둡니다.
- 버튼은 실제로 실행하는 것만 둡니다. 전체 업데이트 확인, 후보 확인, 지정한 패키지 확인, 검사만, 반영은 폼의 POST이고, 보고서, 미리보기 열기, 기록은 링크입니다.

## 6. 초점과 조작 크기

- 초점은 3px 먹남색 외곽선과 그 안쪽 2px 꿀색 띠 두 겹입니다(`:focus-visible`). 레일 위에서는 외곽선이 흰색입니다. 어느 바탕에서든 둘 중 하나는 보입니다. 외곽선을 지우지 않습니다.
- 선택은 채움(꿀색 바탕과 먹남색 테두리), 초점은 바깥 고리로 구별합니다.
- 버튼, 입력, 탭, 막대의 링크는 높이 2.75rem 이상입니다. 넓은 화면의 표 안 버튼과 후보 링크만 2.25rem이고, 46rem 미만에서는 다시 2.75rem입니다.
- 움직임은 쓰지 않습니다. `prefers-reduced-motion`이 없을 때만 조각 주소로 가는 스크롤을 부드럽게 합니다.

## 7. 화면 너비별 배치

| 너비 | 탐색 | 목록 | 검사 근거 |
| --- | --- | --- | --- |
| 46rem 미만 | 막대(열린 프로젝트만) | 행이 블록으로 쌓임 | 고른 행 바로 아래, 접힌 채 |
| 46rem 이상 | 막대(프로젝트는 옆으로 스크롤) | 표 | 고른 행 바로 아래, 접힌 채 |
| 64rem 이상 | 막대 | 표 | 오른쪽 고정 패널 |
| 80rem 이상 | 레일 | 표 | 오른쪽 고정 패널 |

- 검사 근거는 고른 행 바로 다음 줄의 칸(`#candidate-evidence`)에 씁니다. 64rem 미만에서는 주소가 그 칸을 가리킬 때(`:target`)만 펼쳐지므로, 후보를 고르면 그 행 아래에서 바로 열립니다. "검사 근거 접기"는 같은 주소의 `#picked`로 갑니다.
- 64rem 이상에서는 그 칸의 높이가 0이고 패널이 화면 오른쪽에 고정됩니다. 그래서 같은 주소가 고른 행을 화면 안으로 데려옵니다. 패널을 쓰는 화면은 `<body class="split">`이고 본문과 아래 주석이 패널 폭(`--inspect`)만큼 자리를 비웁니다.
- 업데이트 후보는 모든 너비에서 후보 하나가 카드 하나입니다. 기록의 표는 표 안에서만 옆으로 스크롤합니다.
- 어느 너비에서도 페이지 전체가 옆으로 넘치지 않아야 합니다.

## 8. 상태별 화면

| 상태 | 표시 |
| --- | --- |
| 프로젝트 없음 | 등록 카드 하나: 프로젝트 폴더 선택(채운 버튼), 그 아래 접힌 "폴더 경로 직접 입력", 옆에 등록한 뒤 하는 일 세 줄 |
| 아직 확인 안 함 | 상태 문장, 직접 의존성 행의 "후보 확인" 버튼, 나머지는 빈 셀과 "미확인" |
| 열 후보 없음 | 패널에 판정 표시 읽는 법 |
| 목록이 빔 | `.empty`(빈 육각 셀과 다음에 할 일) |
| 멈추는 오류, 기지 악성 일치 | `.error`(위험색 띠와 바탕) |
| 보류, 확인이 필요한 항목 | `.warning`(보류색 띠와 바탕) |
| 폴더 없음 | 제목 아래 `.error`, 폼과 버튼 없음, 기록은 그대로 열림 |
| 입력 오류 | 해당 입력란 바로 위에 `role="alert"`, 입력란에 `aria-invalid` |

## 9. 지키는 제약

- 스크립트, 외부 글꼴, 외부 이미지를 쓰지 않습니다. 템플릿에 `style` 속성과 `<style>`을 쓰지 않고, CSS에 `url()`을 쓰지 않습니다(CSP `style-src 'self'`).
- 모든 링크와 폼은 세션 주소(`/s/<세션>/`) 아래입니다. 조각만 있는 링크는 건너뛰기 링크 하나뿐입니다.
- 패키지에서 온 문자열은 템플릿의 `{{ }}`로만 내보냅니다(자동 이스케이프와 제어 문자 치환). 패키지 표에서 패키지 하나를 적는 행의 `tr`, `th`, `td`에는 속성을 붙이지 않고, 선택 표시는 그 행 안의 링크에 둡니다.
- GET은 파일과 이력만 읽습니다. 화면을 보는 것으로 npm을 실행하거나 네트워크에 접근하지 않습니다.

## 10. 확인 방법

1. `tests/`에서 `python -m unittest test_dashboard test_dashboard_picker test_dashboard_picker_stop test_dashboard_report_assets test_dashboard_inspector test_dashboard_overview`를 실행합니다.
2. 브라우저 너비 390, 820, 1100, 1440px에서 패키지 화면을 엽니다. 페이지가 옆으로 스크롤되지 않는지, 표가 7절의 배치로 바뀌는지 봅니다.
3. 후보를 고릅니다. 주소가 `item=<실행>.<위치>#candidate-evidence`로 끝나는지, 좁은 화면에서는 그 행 아래에 근거가 펼쳐지고 넓은 화면에서는 그 행이 패널 옆에 보이는지 확인합니다.
4. Tab 키로 후보를 골라 Enter를 누릅니다. 근거 패널에 초점이 도착하고, 넓은 화면의 “목록에서 이 행 보기”를 누르면 선택한 후보로 돌아가는지 확인합니다.
5. Tab 키로 건너뛰기 링크부터 차례로 이동하며 초점 고리가 레일, 작업면, 꿀색으로 채운 선택 위에서 모두 보이는지 확인합니다.
6. 판정마다 셀 모양과 글자가 함께 있는지, 꿀색이 선택과 브랜드에만 쓰였는지 봅니다.
7. 화면에 가짜 기록, 점수, 건수가 없는지, 모델과 기지 악성 목록 기준 시점이 저장된 값이거나 "보고서에 기록 없음"인지 확인합니다.

## 근거

`ui-ux-pro-max` 검색 결과 중 제품에 맞는 것만 따랐습니다. Data-Dense Dashboard 스타일(레일 폭 240px, 촘촘한 간격, 고정 표 머리), Table Handling(좁은 화면의 표는 블록으로 바꾸거나 표 안에서만 스크롤), Horizontal Scroll(본문이 화면 폭에 맞음), Color Only(색과 함께 모양과 글자), Compact Label Overflow(칩은 한 줄), Focus Not Obscured, Deep Linking(상태를 주소에 둠), Empty States입니다. 함께 나온 Enterprise Gateway 패턴(영상 히어로, 고객사 로고, 영업 문의)은 마케팅 페이지용이라 쓰지 않았고, Fira 글꼴 권고는 외부 글꼴이라 쓰지 않았습니다. 목록과 상세를 나란히 두는 패턴은 검색에 일치하는 항목이 없어 위 규칙으로 직접 정했습니다.
