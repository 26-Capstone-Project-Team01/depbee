# 다음 개발 순서

CLI, 로컬 대시보드, stdio MCP, GitHub Action은 공통 보고서에 기지 악성 일치, 정적 규칙 여섯 개, ML 점수를 표시한다. 대시보드는 프로젝트 등록, 업데이트 미리보기와 반영, 검사 이력과 점수 추이를 지원한다. Claude Code에서는 선택형 설치 가드로 변경된 lockfile을 설치 직전에 다시 검사할 수 있다. [사용 안내](usage.md) · [가드 사용법](claude-guard.md)

## 1. depbee 개발 계속

탐지 모델은 개발 중이다. 현재 동봉 모델로 depbee 개발과 회귀 검증을 진행한다.

## 2. 모델 후보 인계 후 규칙 판정표 대조

- 규칙 담당자의 D06 판정표와 모델 담당자의 최종 후보를 받는다. 후보에는 native LightGBM 파일, 특징 이름과 순서, 데이터·분할·추출기 버전, 검증 자료에서 선택한 임계값과 근거가 필요하다. 동봉 모델 D04-E00의 0.5는 학습 기본값이다. [현재 manifest](../src/depbee/assets/model/manifest.json)
- 같은 버전 쌍에서 규칙별 적중·미적중·판정 불가와 기지 악성 일치를 대조하고, 학습 때의 특징·점수와 제품이 계산한 값이 일치하는지 확인한다. 정상 오탐과 악성 미탐을 함께 보고 교체 여부를 기록한다. 두 모델의 점수를 합치는 후보를 선택하면 혼합 비율과 독립 자료로 정한 임계값도 검증한다. [결합 모델 연동 실험](https://github.com/26-Capstone-Project-Team01/model-training/pull/16)
- 교체가 결정되면 모델 파일과 manifest·해시를 함께 바꾼다. 특징 정의나 배포본 비교 규칙이 바뀌면 스키마, 분석기 고정 커밋, 비교 기준 선택 코드도 함께 맞춘다. 분석기가 바뀌면 `.[extract]` 설치 후 `PinnedLoaderTests`가 모두 실행되는지 확인한다. [연결 규약](contracts.md)

## 3. depbee 개발 완료 후 커밋 정렬과 최종 리허설

- 시연용 wheel을 발표 PC의 새 가상환경에 설치하고 CLI, 대시보드, MCP를 그 설치본으로 실행한다. 소비자 저장소의 GitHub Action도 같은 제품 커밋에 고정한다.
- 같은 lockfile 변경의 패키지·버전, 모델 ID, 색인 기준 시점, 규칙 결과, 점수와 판정을 네 보고서에서 대조한다. 정상 변경, 기지 악성 일치, 분석 보류에서 각 진입점이 표시하는 조치도 확인한다. [시연 절차](demo.md) · [Action 판정 정책](ci-cd.md)
- Claude Code 설치 가드를 시연할 때는 발표 환경에서 직접 설치 요청이 훅에 차단되고, `depbee guard ci`를 통한 정상 변경이 설치되는 흐름을 이어서 확인한다. 11월 27일에는 Windows에서 정상 변경 한 건의 실제 npm 설치까지 확인했다. [검증 기록](validation.md)

## 후속 후보

Actions의 `report.json`을 대시보드에서 열기, 같은 변경의 모델별 점수 비교, CLI 결과로 HTML 보고서 만들기, 정책 설정과 버전별 승인 기록은 통합 검증 이후의 후보다.
